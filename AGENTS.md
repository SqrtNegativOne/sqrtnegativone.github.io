# Repository Guide — two static SvelteKit apps

This repo hosts **two independent SvelteKit apps** plus a Tauri admin dashboard:

- `site/` → **`sqrt.fyi`** — blog, feed, microblog, now, questions, media library, colophon, and the unlisted `/main` page.
- `cv/` → **`cv.sqrt.fyi`** — home, `/about`, `/projects`, `/skills`, `/now`.
- `shared/` — cross-app code (visual primitives + media helpers), imported via the `$shared` alias in both apps.
- `admin/` — Tauri + SvelteKit admin dashboard. See `admin/AGENTS.md`.

The `site/` is the personal website, for my friends and all. `cv/` is the version of the website that goes on my resume and linkedin, among other professional pages. `admin/` is a personal application for personal use, that allows the user to non-programmatically modify site content, and also display information that pertains to the user and no-one but the user.

Each app owns its own `package.json`, `bun.lock`, `svelte.config.js`, `vite.config.js`, `tsconfig.json`, `wrangler.jsonc`, `.svelte-kit/`, and build output. **Run `bun install` and all commands from inside the app directory.**

## Tech Stack Overview
- **Apps**: [SvelteKit](https://svelte.dev/) (Svelte 5) + [Tailwind CSS v4](https://tailwindcss.com/).
- **Hosting**: Two **Cloudflare Workers** with static assets (`@sveltejs/adapter-cloudflare`), deployed by `.github/workflows/deploy-site.yml` and `deploy-cv.yml` on push to `main` (path-filtered).
- **Database** (site only): **Cloudflare D1** (binding `DB`) stores contact-form submissions. See “Contact Form & D1” below.
- **Blog Engine** (site only): Markdown via [Velite](https://velite.js.org/), rendered natively through `site/src/routes/blog/`; posts in `site/blog/posts/*.md`.
- **Package Manager**: **Bun**. Don't use npm.

## Repository Structure
- `shared/components/` — `Seo`, `AsciiBackground`, `NotFound`, `MenuOverlay`, `NowBook`, and the media-library components (`MediaGallery`, `MediaGalleryCard`, `MediaGroupHeading`, `MediaTable`, `MediaViewToggle`, `FilterSort`, `LibraryRow`, `RatingChart`, `StatusBadge`, `TypeBadge`).
  - The grouped gallery/table views live in `shared/` so the site and admin render the same media UI; each page owns only its filters, modals, and data loading.
  - `Seo.svelte` takes a `base` prop (defaults to `https://sqrt.fyi`; cv passes `https://cv.sqrt.fyi`).
  - `MenuOverlay.svelte` takes an `items` prop; each app defines its own `NAV_ITEMS` and passes them in.
  - `NowBook.svelte` is the bookmark-tab selector used by both `/now` pages; it takes pre-rendered HTML so each app keeps its own Markdown renderer.
- `shared/lib/arcs.ts` — the `Arc` model, date parsing, ongoing filtering, and date formatting for `/now`.
- `shared/lib/mediaLibrary.ts` — `MediaViewMode`, `groupMediaByType()` (groups library items by `type` in `media-properties.json` order; both apps use it for their default grouped views, with groups collapsed until expanded), and `toggleSort()` for sortable table headers.
- `shared/lib/mediaLog.ts` — event model helpers for the media log: date parsing/formatting in local wall time, `checkpoint` formatting, history derivation, month grouping, and the per-type default progress unit.
- `shared/data/now.json` — the cross-app arc data consumed by both the site and cv `/now` pages (and the admin app).
- `site/src/routes/` — `/` (client-side redirect stub to `cv.sqrt.fyi`), `/main` (unlisted, noindex, no global menu — uses a self-hosted pixel font), `/blog`, `/blog-afterdark`, `/feed.xml`, `/sitemap.xml`, `/microblog`, `/now`, `/questions`, `/questions.md`, `/media-library`, `/contact`, `/colophon`.
- `site/src/routes/api/contact/+server.ts` — non-prerendered `POST` endpoint behind the `/contact` form; writes to the D1 `DB` binding.
- `site/migrations/` — D1 SQL migrations (applied with `wrangler d1 migrations apply`).
- `site/blog/posts/` — Markdown posts; `site/blog/_data/` — static data (e.g. `fonts.json`) shared with the admin app.
- `site/static/` — `media/` (13 MB, never copy elsewhere), `blog-images/`, `velite/`, plus machine-readable files `robots.txt`, `llms.txt`, `.well-known/security.txt`. **Everything here is served verbatim**: never put private data under `static/`.
- `cv/src/routes/` — `/`, `/about`, `/projects`, `/skills`, `/now`, `/sitemap.xml`.
- `cv/static/` — cv-only assets (`portraits/`, `projects/`, `quotes/`, `logos/`, `thomas-test.html`).
- Both apps duplicate a small set of design-system static assets: `fonts/`, `fonts.css`, `vendor/`, `favicon*`, `apple-touch-icon.png`, `manifest.webmanifest`, `.well-known/security.txt`.
- `site/src/worker-configuration.d.ts` — generated by `bunx wrangler types src/worker-configuration.d.ts`; re-run after changing `site/wrangler.jsonc`.
- `dev.bat` — starts the **site** dev server (`cd site && bun run dev`).
- `admin.bat` / `admin-build.bat` / `test.bat` — admin app scripts.

## Development Commands
All commands use `bun` and run **inside `site/` or `cv/`**.

- `bun run dev` — Vite dev server (site adds Velite watch mode).
- `bun run build` — production build into `.svelte-kit/cloudflare`.
- `bun run lint` — `eslint` + `oxlint`.
- `bun run check` — `svelte-kit sync` + `svelte-check` (types + a11y).

**Cloudflare:**
- `bunx wrangler dev` — run the built Worker locally with emulated bindings.
- `bunx wrangler deploy` — deploy the Worker + assets.
- `bunx wrangler types src/worker-configuration.d.ts` — regenerate Worker types after changing `wrangler.jsonc`.
- `bunx wrangler d1 create sqrt-fyi-messages` — one-time creation; copy the returned `database_id` into the `DB` binding in `site/wrangler.jsonc`.
- `bunx wrangler d1 migrations apply sqrt-fyi-messages --local` / `--remote` — apply migrations locally / to production.
- `bunx wrangler d1 execute sqrt-fyi-messages --remote --command "SELECT id, created_at, country, substr(body,1,80) FROM messages ORDER BY id DESC LIMIT 20"` — read recent submissions.

## Contact Form & D1
- The `/contact` page is **prerendered** and posts JSON to `/api/contact` (marked `export const prerender = false`), so the form works while the page stays static. A no-JS `<form>` fallback redirects back to `/contact?sent=1`.
- `site/wrangler.jsonc` declares the `DB` D1 binding; `site/migrations/*.sql` define the `messages` table. The deploy workflow applies migrations before deploying.
- The handler validates/limits the message (5000 chars), uses a hidden honeypot field, and rate-limits by a **daily-rotating SHA-256 hash** of the client IP (raw IPs are never stored).
- **Reply channel** (optional): below the textarea the form renders `[method select][handle input][Send]`. Method ids, labels, icons, placeholders and link builders live in `shared/data/contactMethods.ts` (`email`, `whatsapp`, `phone`, `sms`, `discord`, `linkedin`, `steam`; first entry is the default) and are shared with the admin messages view. The API rejects unknown ids, stores them as `messages.contact_method`, and stores the trimmed handle (`contact_handle`, max 200 chars) or `NULL` when empty — both added by `site/migrations/0002_add_contact_details.sql`. Add a method there (plus a migration if the storage shape changes), not inline in the page.

## Now / Arcs
- `sqrt.fyi/now` and `cv.sqrt.fyi/now` are the same page rendered from `shared/data/now.json`; there are no daily `/now/[date]` entries anymore.
- Each arc has `id`, `title`, `startDate`, an optional `endDate` (date-only `YYYY-MM-DD`), `audience` (an array containing `professional`, `personal`, or both), and a Markdown `description`.
- Each page only shows **ongoing** arcs, using `getOngoingArcs()` from `shared/lib/arcs.ts`. An arc has started once `startDate <= today`; it ends when `endDate` is present and in the past. **A missing/blank `endDate` means the arc is open-ended and stays ongoing indefinitely.** Because both apps are prerendered, “today” is the build date; rebuild/redeploy when an arc starts or ends.
- Audience filtering: `sqrt.fyi` asks for `personal`, `cv.sqrt.fyi` asks for `professional`; an arc tagged with both appears on both.
- **Never use the word “arc” in visible cv copy.** The CV page calls them “focus areas” and labels the tab strip `Focus areas`; `NowBook.svelte` takes its accessible label as a prop for this reason.
- `shared/components/NowBook.svelte` renders the selector (vertical bookmarks on desktop, a horizontal scroll strip on mobile) plus the description panel. It uses Svelte scoped CSS only (cv’s `index.css` does not scan `shared/` for Tailwind classes).
- The admin `/now` page edits the same file through `readData('now')` / `writeData('now', …)`; keep its validation aligned with the model (valid dates, end ≥ start, at least one audience, non-empty Markdown description).

## Media Library & Log
- `site/static/media/media.json` is the public shelf: metadata, rating, status, notes, hidden. It is served at `/media/media.json` and imported into the client bundle, so **never store private data there**. Dates are no longer stored on items; start/finish/checkpoint come from the log.
- `site/src/data/media-log.json` is the **public projection**: only `visibility: "public"` events. `add` events are included so the modal can show the Added date, but the Log timeline filters them out.
- `admin/data/media-log.json` is the **master log**, including private events. It is gitignored and read only by the admin through `readTextFile`/`writeTextFile` (`MEDIA_LOG_MASTER` in `admin/src/lib/db.ts`). Never move it into `site/` or `shared/`.
- Events: `add | start | checkpoint | finish | drop | shelve | resume | note`. `at` is local wall time (`YYYY-MM-DD` or `YYYY-MM-DDTHH:mm`) so grouping does not shift under a UTC build. `round` supports rewatches; a checkpoint carries optional `unit` (`episode|season|page|chapter|hour|percent`), `value`, and `total`. The per-type default unit lives in `shared/lib/mediaLog.ts`.
- Visibility is **private by default**. The admin writes the master and the projection on every save; a public event reaches the site only after commit + rebuild.
- Admin `/media` has `Library | Log` tabs. Quick capture logs an event, can set the date/time, and optionally nudges the item's status (`start/checkpoint/resume` → consuming, `finish` → finished, `drop`/`shelve` → dropped/shelved). The EditModal shows read-only history.
- Site `/media-library` has `Library | Log` tabs; the Log tab and the item modal only ever see public events. The media library is `noindex`.
- Private notes live in `admin/data/media-private.json` (gitignored), not under `site/static/media/`. The old `site/static/media/media-private.json` was removed because `static/` is served verbatim; it remains in git history and at the old URL until the next deploy/history rewrite.

## Coding Guidelines & Rules
- **Svelte 5 Syntax**: Use runes (`$state`, `$derived`, `$props`, `$effect`) instead of Svelte 4 `export let` or `$:`.
- **Rendering**: Each app's `src/routes/+layout.js` sets `prerender = true`; pages are static. A new route that needs the server must opt out with `export const prerender = false`.
- **Tailwind v4**: Use utility classes and `@theme` in CSS; no `tailwind.config.js`.
- **Accessibility (a11y)**: Svelte a11y checks are enforced. Keep the skip link targeting `#main-content` and that id on the main content container in **every layout branch of both apps**.
- **Reduced motion**: Global CSS guard lives in each app's `src/App.css`; gate JS-driven animation (rAF/GSAP) behind `matchMedia('(prefers-reduced-motion: reduce)')` like `AsciiBackground.svelte`.
- **Component-scoped styling**: For injected HTML (`{@html ...}`), use `:global(.class)` in `<style>`.
- **Per-page SEO**: Use `$shared/components/Seo.svelte` (title, description, canonical, OG, optional noindex); pass `base` for the cv app. Site-wide defaults live in each app's `src/app.html`.
- **Cross-app imports**: Use the `$shared` alias. `shared/` is outside each app root, so both `vite.config.js` files need `server.fs.allow: ['..']` for dev.

## Site Blog Engine (Velite + SvelteKit)
- Posts live in `site/blog/posts/*.md` with frontmatter `title`, `date` (YYYY-MM-DD), `description`, `tags`, optional `font` and `draft: true`. Tagging a post `afterdark` routes it to `/blog-afterdark/` and excludes it from the public feed/sitemap/markdown endpoints.
- **Feed**: Atom 1.0 at `/feed.xml` via `site/src/routes/feed.xml/+server.ts`.
- **Markdown source**: each post's raw Markdown at `/blog/<slug>.md` via `site/src/routes/blog/[slug].md/+server.ts`.
- **Machine-readable files**: keep `site/static/llms.txt`, `site/static/.well-known/security.txt`, and `site/static/robots.txt` in sync when adding pages/feeds/URLs. The sitemap is generated by `site/src/routes/sitemap.xml/+server.js` (post `<lastmod>` from frontmatter); `/main` and the `/` redirect stub are intentionally excluded.
- **Vendor assets**: self-host third-party CSS/fonts under `static/vendor/`; don't reintroduce CDN links.

## Cloudflare deploy notes
- `sqrt.fyi/` performs a **client-side** redirect to `cv.sqrt.fyi` — `adapter-cloudflare` serves prerendered assets from `env.ASSETS` and bypasses SvelteKit hooks, so do not convert `/` into a server redirect.
- Owner-only setup: ensure `CLOUDFLARE_API_TOKEN` / `CLOUDFLARE_ACCOUNT_ID` repo secrets exist and point the `sqrt.fyi` zone at Cloudflare. Custom domains are created on first `wrangler deploy`. For the contact form, also create the `sqrt-fyi-messages` D1 database once and paste its id into `site/wrangler.jsonc`; the workflow then applies `site/migrations/` on each deploy. If you ever remove the D1 binding, drop the migration step from `deploy-site.yml`.
